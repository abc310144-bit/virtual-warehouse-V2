# 虛擬倉配貨與出貨邏輯

> 業務規則紀錄，供虛擬倉 2.0 功能開發與後續 API 設計參考。

## 階層定義

| 層級 | 名稱 | 說明 |
|------|------|------|
| L1 | 總倉 | 實體庫存來源，所有商品實際存放處 |
| L2 | 通路分組 | 中介虛擬倉，將多個 L3 銷售通路歸為同一共享池 |
| L3 | 銷售通路 | 實際接單、出貨的銷售端（如 PChome、MOMO 等） |

---

## 雙軌配貨邏輯

L1 總倉配貨採**雙軌、具彈性**方式，不限定只能配至單一層級：

### 軌道一：配至 L2 通路分組

- 將庫存從 L1 配貨至某個 **L2 通路分組**
- 該 L2 底下所有 L3 銷售通路共享此池庫存

### 軌道二：直配至 L3 銷售通路

- L1 總倉可**跳過 L2**，直接將庫存配貨至**特定 L3 銷售通路**
- 適用於需獨立控管、不與同組其他通路共享的場景

> 兩種配貨路徑可並存，依業務需求選擇，非互斥。

---

## 出貨扣減邏輯（L3 訂單）

當 **L3 銷售通路產生訂單需要出貨**時：

1. **不強制**要求商品必須已預先分配至「該 L3 通路」
2. 只要商品在**其所屬 L2 通路分組的共享池**內有可用庫存，即可：
   - 直接進行訂單扣減
   - 完成出貨

### 白話說明

- L3 訂單不必「點名」扣自己名下的庫存
- 可從同 L2 分組的**共享庫存池**扣減
- 降低配貨前置作業的硬性限制，提升出貨彈性

---

## 與 UI 的對應關係

| UI 概念 | 對應層級 | 備註 |
|---------|----------|------|
| 總倉 | L1 | 篩選「總倉」時檢視 L1 實體庫存 |
| 通路分組 | L2 | 設定與篩選用 |
| 銷售通路 | L3 | 設定與篩選用；出貨扣減的最終觸發端 |
